All implementations in src/scoped_agent_api; no runtime import from evaluation or demo_insecure. No fixture secrets/real tokens in logs. Namespace modules may be added in owned paths; INT owns package root and metadata.

DL1 owns ports/ and host/. Public seam: ports.clock Clock.now() UTC datetime; SystemClock and VirtualClock. host.store Store(path) with transaction() context returning sqlite3.Connection, initialize() explicit only. host.policy PrincipalContext(subject, actor_kind, client_id, grant_id, scopes:frozenset[str], resource); authorize(context, action) raises DomainError(code,status,required_scopes=()). host.commands CommandService(store, clock) execute(action, principal, arguments, idempotency_key, surface="api") -> dict; get/list methods via command action names list/get; DomainError in host.policy. No auto-initialize on import.

DL2 owns authz/, api/, ui/. API invokes CommandService; authz documents principal resolution seam and shared per-grant locking for DL3. AS/library spike is runtime-deferred, no fallback/rewrite claim. DL2 may support metadata/auth routes without importing unavailable packages at module import where feasible.

DL3 owns webhooks/, receivers/, demo_insecure/. Declare subscriptions/outbox schema in owned paths. Reconcile DL1 domain event inserts with table contract in host migrations. webhooks locks provide shared grant lock used by DL2 revoke; no separate lock registry. Dispatch accepts injected transport, clock and grant validator; receiver verify/insert before ACK. No outgoing calls during construction.

DL4 owns cli/, agent/, fixtures/tasks (development-only), fixtures/m20-stub, contracts/v1, docs (except this file), scripts/ (except INT admission note). CLI HTTP only via injected HTTPX adapter; call documented /v1 routes with bearer headers. No real token IO or .env reading. CLI JSON exits 0/2/3/4/5; default dry-run. Contract readiness stub_only, no measured values or false producer_commit. All task examples are developer examples, never oracle/evaluation data.

Operation names: list,get,create,edit,submit,approve,close,cancel. Arguments use id, expected_version, title, assignee and capability_id as relevant.
