# In-memory fixture OAuth client source

Source construction only, runtime unverified. The authorization server and resource API are separate Flask applications owned by DL2; OAuthController uses only configured AS endpoints and Session uses only its configured resource base. No second authorization server, successful-login simulator or Authlib fallback is provided. DL2 `/authorize` and `/token` deliberately return authlib_spike_pending until a separately authorized runtime spike approves activation. This client must surface that refusal and stop.

`OAuthConfig` names exact issuer, resource, client_id, redirect_uri, allowed_clients, allowed_redirect_uris, allowed_scopes, consent_fixture_id and actor_kind (`agent` or `human`). The trusted launcher supplies those allowlists from a preauthorized fictional fixture manifest, never a task, HTTP challenge, environment or token file. HTTP is allowed only for exact local fixture hosts; no production identity claim. The fixture resolver owns the mapping from consent_fixture_id to actual fictional subject; the client does not post subject/grant authority.

`OAuthController(config, transport, consent, clock)` receives an OAuthTransport and an explicit fixture consent adapter `consent(authorization_url)->callback_url|None`. The adapter must require the preauthorized fixture allow/refuse decision, contact only that supplied authorization URL in a later permitted runtime, refuse redirects except the final exact configured callback, avoid logs, and return the actual callback URL. Returning invented success/code values is not permitted. It starts no browser or process. The clock callable returns aware UTC datetimes. HttpxOAuthTransport is the bounded, no-proxy/no-redirect GET/POST form adapter source; nothing executes on module import.

`login(scopes)->bool` discovers only the configured AS metadata, checks exact issuer/endpoints and advertised protocol features, creates in-memory state/verifier and S256 challenge, binds requested resource/client/redirect/scopes and explicit fixture consent, and processes the actual returned callback once. It rejects duplicate/missing/unexpected callback fields, wrong redirect/state/issuer or error responses before code exchange. The client exchanges the code using the exact resource and redirect plus verifier. No browser URL or callback is logged. Tokens are private, memory-only, and excluded from dataclass repr.

`bearer()->str` exposes only the current in-memory resource-bound access token to Session, and refuses stopped/expired authority. `step_up(scopes)->bool` requires explicit new consent for the requested union; Session owns the one-step-up-per-resource/operation limit. Agent approval scope is prohibited regardless of allowlist. `refresh()->bool` is explicit and must run before access expiry; expiry permanently stops this controller. Refresh rotates refresh values, binds resource and client, and cannot widen the previously granted scopes. `revoke()->None` calls the configured RFC7009 endpoint and permanently closes/clears the local controller even if transport fails. Protocol failures/refused consent do not reopen authority. The AS remains responsible for durable token/grant/family and webhook revocation.

`AuthenticatedSessionFactory(controller_factory, resource_transport, initial_scopes)` is a trusted injected callable for CLI/task execution. controller_factory(actor_kind) must return a correctly configured fresh controller, retained by the fixture launcher if it will later call refresh/revoke. The factory maps CLI user to protocol human (agent remains agent), checks actor equality, obtains an actual login result, and injects bearer and step_up into Session. It cannot authorize by a dataclass, task or `--as` flag. A refusal is a CLI denial, never a fabricated success. The CLI validates dry-run/consent/key requirements before invoking the factory. Scripted task factory is always agent-kind; developer task mutations default to dry-run without login. scripts/demo.journey accepts the same optional factory; standalone demo does not create an environment, fixture authority, or listener.

No credentials are accepted in CLI flags, task fields or files. Configuration and temporary protocol values remain in memory and are not export artifacts. Runtime activation must verify allowlist setup, exact metadata and callback processing, S256/code replay, token scope/resource/expiry binding, refresh rotation/reuse, consent refusal, stopped state and no-call dry-run, real installed CLI/API parity, separate-app routing, and server Authlib spike behavior. Source inspection is not interoperability/security acceptance; independent admission and license gates remain pending. M20 readiness remains stub_only.
