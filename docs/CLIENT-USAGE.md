# CLI and scripted client source

Construction only; runtime unverified. The installed `wo` entrypoint is declared in package metadata. After a later authorized install, `wo --json create --arguments '{"title":"Inspect pump","assignee":"tech.lee"}'` emits one m14.cli.v1 dry-run envelope and sends no HTTP. Mutations require `--apply-fixture`, an injected disposable FixtureConsent and in-memory authenticated Session. Standalone applied/read calls fail closed with fixture_session_required/fixture_consent_required until the fixture launcher is integrated. No token files, environment lookups or command-line bearer values are supported. `--as` is a local denial guard only; the server token defines actual identity.

An embedding launcher calls `scoped_agent_api.cli.wo.main(argv, session=session, consent=consent)`. Construct Session(resource, HttpxTransport(), bearer=callback) with an exact configured fixture resource and a callback returning only a short-lived in-memory token. Obtain it from the separately authorized mock flow, never from task text. The launcher must verify that FixtureConsent names its generated disposable workspace and records human confirmation; a dataclass by itself is not a server security boundary. No built launcher or OAuth interoperability claim is made here.

CLI stdout carries one versioned envelope; diagnostics go to stderr. Exit 0 success/dry-run, 2 input, 3 denial, 4 conflict, 5 transport/server failure. `--help` is argparse text. Never supply credentials in --arguments. Transport disables redirects/environment proxies and bounds requests to five seconds. No automatic transport retry can duplicate a mutation. Server-side current grants, idempotency and CAS remain authoritative. CLI sends X-M14-Surface: cli; scripted API sends api.

Operations: list/get/create/edit/submit/approve/close/cancel, challenge/confirm, subscriptions/subscription/subscribe/disable/enable, deliveries/delivery/replay/recover. `id` is encoded into item routes; challenge sends {id}; recovery uses /v1/deliveries/recover. POST/PATCH require an idempotency key. Argument fields follow the API; use expected_version for transitions and capability_id for human approval. Agent mode refuses confirm/approve locally as well as retaining the host boundary. Human mode never invents a human principal.

Scripted `run_task` accepts m14.task.v1 only, runs sequentially, and stops on a failed result. Mutations default to no-call dry-run. A Session permits at most one insufficient-scope step-up per resource/operation, asks its injected consent callback for the union of current and challenged scopes, refuses approval scope, and stops after a 401/403 or refused consent. This is the resource request layer; metadata discovery, PKCE authorization, issuer/state checking, refresh rotation and revocation require the separate fixture authorization integration and later runtime checks. They have not been proven by this source.

Developer samples and M20 transcripts are not independent labels, test outcomes or durable effects. effect_ref is null until an actual effect can be observed. Interface readiness remains stub_only. No measured headline, license adoption or independent admission is claimed.

Client response note: error envelopes use locally generated nonsecret problem metadata and a closed set of declared server codes. The local request_id placeholder is not a server audit correlation receipt; original server request-ID propagation remains deferred until a bounded safe format is reconciled. No effect or request correlation claim is inferred from that value.
